Counterfactual Denial Attribution

When AI agents reach for tools, security shapes what happens next.

Exploring how security denials and their explanations
influence the behaviour of tool-using AI agents.

01 The research problem

Is it the denial,
or what the denial says?

Can controlled counterfactual execution distinguish information leakage caused by a security denial event from leakage caused by the explanation accompanying that denial?

Research question · under investigation

Event

Whether an action was blocked at all, with no reason given.

Reason

What the denial message reveals about why, and what it might hint at.

Counterfactual

Isolated branches that differ only in the feedback the agent receives.

02 How the system works

Every action passes
through the monitor.

  1. 1

    Propose

    The agent proposes a tool call with concrete arguments.

  2. 2

    Evaluate

    The security monitor checks it against every policy layer.

  3. 3

    Allow or deny

    Allowed actions run in a sandbox. Denied actions never execute.

  4. 4

    Feedback

    The agent sees a tool result or denial feedback, then acts again.

  5. 5

    Compare branches

    Isolated counterfactual branches are compared on actual actions and content.

03 Security architecture

An ARM-inspired
layered monitor.

The monitor makes the authoritative ALLOW or DENY decision. Each proposed action is evaluated by the layers in order; the first layer that fails denies it.

  • L1

    Hard boundaries

    Payload limits, sensitive paths HB-2, credential patterns HB-4, call rates.

  • L2G

    Graph provenance

    Tracks where data came from; untrusted data cannot reach a protected sink L2G-TRUST.

  • L3

    Schema-derived

    Constraints derived from tool schemas, such as suspicious free-text parameters SD-1.

  • L4

    Manual policy

    Capability tokens: only permitted tools L4-TOOL, budgets and blocklists.

Denied means not executed

A denied action never reaches the tool. Authorization and execution are recorded separately.

Hash-chained audit

Every action produces a structured audit record, chained with SHA-256 so edits are detectable.

Hidden classifications

An opt-in resource policy lets the evaluator know which resources are protected; the agent does not.
